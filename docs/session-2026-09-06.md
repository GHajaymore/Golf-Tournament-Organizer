## The four findings worth remembering

**Metadata was in `<body>`.** Next 15 streams it; `</head>` closed at char 1,303 and every tag sat at ~70,000. It is only disabled for `htmlLimitedBots`, whose default list is the unfurlers that cannot run JavaScript — so Twitter/Slack/WhatsApp/Facebook were always fine and **Googlebot and ordinary browsers were not**. A canonical in the body is not a canonical. `next.config.mjs` now sets `htmlLimitedBots: /.*/`.

**The app failed its own outdoor bar.** `SUNLIGHT_RATIO` is 7:1 and `sunlightVerdict` returned `ok: false` for **all eleven presets**, because Fairway (3.91:1) was the secondary in every one. Verdigris (10.09) + Optic (13.80) is the first pairing that passes. Existing clubs are unaffected: `themeKey`/`themeSecondaryKey` are non-nullable with SQL literal defaults, so every existing row already stores `sunset`/`fairway`. The migration is `ALTER COLUMN SET DEFAULT` with **no backfill**.

**Changing the TypeScript default alone would have done nothing** — Postgres writes the column default on insert, so `DEFAULT_CLUB_THEME` never reaches a real row. `default-theme.test.ts` reads `schema.prisma` and asserts the SQL default and the constant name the same preset.

**Fonts: three separate faults.** Fraunces was fetched twice under one family name (self-hosted + gstatic). Phosphor came from unpkg behind two render-blocking cross-origin stylesheets. `--font-body` named Inter, which never loaded, while ~141 KB of Geist was downloaded and rendered nothing. `font-hosts.test.ts` guards all three by shape.

## Open

- **No console screen has an `<h1>`.** `PageHeader` renders the screen name as a styled `div`. Found because an e2e test measured `/dashboard` by accident and `h1Count` was 0. Whole-console accessibility gap, untouched.
- **~7.9 MB of inert font formats in the build output.** The Phosphor vendor `@font-face` lists woff2/woff/ttf/svg and webpack emits all four. Deploy weight only — no browser requests them. Documented in #140; trimming needs either deliberately-broken URLs or vendoring 156 KB of CSS.
- **Leaderboard row-reorder motion** — agreed as the one place motion earns its keep (positions changing is real information). Not started. Note `globals.css` already removed hover translation on cards deliberately: *"a moving surface is read as a glitch, not as affordance."* Motion belongs on data changes, not chrome.
- **`--incised`** is declared on both grounds in `page.tsx` and referenced by no rule. Dead token.
- **Nav/UX tiering** discussed, not built: split screens by *where they are used* (on-course vs at-desk), not by audience. The console already has a shipped phone mode below 820px, and `roles.ts` sends players to `/me`, not the console.

## Recommendations, in the order I would do them

**1. Give console screens an `<h1>`.** Every one of them currently has none —
`PageHeader` renders the screen name as a styled `div`. A screen with no
heading is unnavigable by screen reader and the browser's own "jump to
heading" does nothing. This is the largest accessibility gap in the product
and it is a small change: `PageHeader` is one component, and the styling can
stay identical. Assert it in the e2e layout sweep, which already visits every
console route, so it cannot regress on a new screen.

**2. Generate the landing palette from `themes.ts`.** `page.tsx` maintaining a
second set of ~30 colour tokens is the *cause* of the two contrast failures
fixed today, not an incidental detail — it is the only surface `themes.test.ts`
does not reach. Keep the distinct marketing look (lacquer, paper, brass, the
display serif); derive the values from the same ramp functions so contrast is
correct by construction rather than caught afterwards by a test.

**3. Decide the nav tiering, and encode it in data.** On-course screens (every
player screen, plus Score entry, Tee sheet, Live leaderboard, Announcements,
Messages) get phone-first discipline; at-desk screens get density. Put the tier
on the nav item, not in a hand-written list. Critically: do **not** drop
at-desk routes from the phone sweep — `e2e/layout.spec.ts` derives its routes
from the filesystem precisely because a hand list covered 14 of 22. The tier
should change *what* is asserted (touch minimums on the on-course tier), never
*whether* a screen is swept.

**4. Leaderboard row-reorder motion.** The one place motion carries
information rather than decorating: when a score lands and positions change,
animating the reorder says who moved. Everything else should stay still —
`globals.css` already removed hover translation on cards on purpose. Respect
`prefers-reduced-motion`.

**5. Measure before optimising performance further.** Mobile sits at 76. The
two Phosphor fonts are now the largest assets at 279 KB combined, for roughly
fifty distinct icons across 466 usages. **Count the distinct set first** — if
it is under a hundred, an inline SVG sprite is a fraction of the weight and
deletes the 7.9 MB of inert formats at the same time. Do not start that work
on the assumption; measure it.

**6. Replace the `hasColours` heuristic.** `checklist.ts` infers "the club has
chosen colours" from `themeKey !== DEFAULT_THEME`. Now that the default has
moved, every club still on `sunset` reads as having chosen — their branding row
ticks without them doing anything. An explicit "branding touched" flag written
when the club saves is the honest version.

**7. Delete `--incised`.** Declared on both grounds in `page.tsx`, referenced by
no rule. It survived only because a test listed it in a ban-list.

**On process:** reuse one verification server rather than starting one per
check — several accumulated today at ~240 MB each. And run the full six-part
gate once per PR at the end, not at intermediate steps; the unit suite alone is
enough while iterating.

## Traps hit today

- `page.tsx` carries a **second design system** (~30 tokens: `--ground`, `--ink`, `--brass`, `--paper`). It is not covered by `themes.test.ts`, which is why it shipped two contrast failures. `landing-contrast.test.ts` now grades it on **both** grounds — Lighthouse only ever tests the one that renders.
- `e2e/layout.spec.ts` sets `storageState` at file level. A test that visits `/` signed in lands on `/dashboard` and can pass landmark assertions against the wrong page. Assert `pathname` first.
- Theme preview by CSS variable must target the `#club-theme` **wrapper div**, not `<html>` — the wrapper redeclares every token.
- `npm install` gave this worktree its own `node_modules`, shadowing the shared one, and its Prisma client was ungenerated → `prisma/seed.ts` failed type-check on an implicit any. Run `npx prisma generate` **from the worktree**.
- Verification servers: reuse one. Each `next start` left behind ~240 MB; several accumulated across the session.
