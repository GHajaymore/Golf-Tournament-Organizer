## 2. How to work in this repo

The gate, before committing anything non-trivial:

```bash
npx tsc --noEmit && npx vitest run && npx next lint && npm run smoke:all
```

Anything touching handicaps, authorization or money also needs the audit suite,
which requires a real database:

```bash
npx vitest run --config vitest.audit.config.ts
```

`npm run smoke:all` is the whole "Build and smoke" CI step locally — it builds
into `.next-ci` and runs all seven verify scripts against a built server. It is
the one to reach for. `npm run smoke` alone is only the first of the seven.

Hard rules, in short — the full text is in `CLAUDE.md` and it is not optional:

1. Never write to an event holding real people. Production is full of them.
2. The GitHub repo is **public**. No player PII in commits, fixtures, logs or
   screenshots.
3. `main` auto-deploys. Do not push to it without saying so.
4. Commit with explicit paths. Never `git add -A`.
5. Never `git stash` — the stash stack is shared across worktrees.
6. Never `prisma migrate reset`.
7. The app calculates and records money. It never moves money.

## 4. What shipped, and the rules now in force

Each of these has a test that fails if it is undone. The reasoning lives beside
the code; this is only an index.

- **A league is won on points, not points per hole** (#565). `chargedHoles` in
  `stroke-agg.ts` charges a **settled** round in full to everyone and only the
  round in flight at holes played. **`chargedHoles` must not read
  `Stage.closedAt`** — it derives "settled" from *not the round on the board*,
  which works with no organizer action. Switching it would charge nothing until
  a club closed something and would regress this fix for every existing event.
- **A board prints the figure it ranked on** (#566, and the test
  `board-prints-what-it-ranked-on.test.ts` enumerates all five ranking units).
  This defect shipped three times on three different units before the axis was
  enumerated. Do not pin this rule on one board's fixture again.
- **An organizer can close a round** (#577). `Stage.closedAt`, nullable, null
  meaning open. On a **stroke** board a player with no card for a closed round
  holds no position. On a **points** board nothing changes — a missed week
  already costs its points. The `!stableford` gate is the half a tidy-up will
  break; there is a test that fails by name if it goes.
- **Launch gates the player app** (#583). `Event.accessGated`, default true,
  backfilled **false** for every tournament that existed. The gate is `draft`
  **only** and deliberately not `!isLaunched` — pre-launch is three statuses,
  and gating registration shuts players out exactly when they want to see they
  are entered. The test pins this as a *difference*, because "surely this is
  just `!isLaunched`" is the refactor that reintroduces it.
- **Brackets are named the way a club names them** (#576): `single` → one
  **Main draw**; `split` → **Flight A / Flight B** (drawn on rank, explicitly
  not a consolation); `plate` → **Main draw / Plate**. `BracketKind` stays
  `winners | consolation` because it spells stored slot keys.
- **Server actions authorize on `role`, never `viewRole`** (#585).
  `one-answer-about-who-you-are.test.ts` sweeps `src/app/actions` from disk.
  One difference deliberately left: `card-photo.ts` restricts course-card
  reading to admin only where its siblings allow assistants — that is about
  *which staff* may act, and is unsettled on its own terms.

Two migrations were added: `81_stage_closed_at` and `82_event_access_gated`.
**Both were renamed by hand** from Prisma's timestamp to this repo's numbering.
Migrations replay lexicographically and CI builds a fresh database every run, so
a `2026…` name sorts into the middle of history. `82` also carries a data
statement (`UPDATE "Event" SET "accessGated" = false`) — that backfill is the
point of it, and without it every stored tournament would be gated.

## 6. The only thing that needs Ajay

**`CRON_SECRET` is not set on the Vercel project.** Do not try to set it
yourself; it is a credential and it is his to enter.

What it does: `/api/cron/expire-rounds` deletes `Event` rows whose `expiresAt`
is set and past, cascading. `expiresAt` is written in exactly one place — when
somebody starts a **casual round** — and is null on every real tournament, so
the sweep cannot touch a club's data. Scheduled daily at 03:00 in `vercel.json`.

With the secret unset the route returns **401 to everything, including Vercel's
own call**, so the sweep has never run. Every abandoned casual round is still in
production and the free tier's "results are not kept" promise is unenforced.

The route fails **closed** on purpose — its docstring is explicit that "no
secret configured, so let it through" would publish an unauthenticated
delete-by-clock endpoint. Once the secret is set, expect the first sweep to be
substantial rather than a no-op; the batch limit spreads it over several nights,
which is the safe behaviour.

## 7. Traps that cost time this session

Written down because each was paid for once already.

- **A grep answers about counts and absences, and lies about both.** Searching
  `seed-club.mjs` for the wrong identifier produced "the seed never sets this",
  which was false and shipped as PR #568 before being reverted in #570. Before
  writing "the code never does X", get the identifier from its **definition** —
  the schema, the type, the function — and confirm the search finds a known
  positive.
- **Prove a new test can fail.** Mutate the thing it covers, watch it go red,
  put it back. A control cell caught a change that would have fixed a symptom
  that no longer existed *and* overridden an earlier decision; it was reverted
  unshipped.
- **The build is the lint that counts.** `next lint` passed a const used before
  its definition; `next build` failed it.
- **Every screen needs an `<h1>`.** A panel with a styled span instead turned 30
  lifecycle checks red.
- **Read a guard before updating it.** Several fired on correct changes this
  session and every one was pointing at something real — a clone policy needing
  a ruling on a new field, a scoped control offered where it did nothing, a
  fixture that could not reach the state being tested.
- **Verify a merge landed**, with `git show origin/main:<file> | grep -c`, not
  by trusting the word MERGED. That habit is what caught #568.
- Prisma field names: read `prisma/schema.prisma`. A guessed column name throws
  a validation error that dumps a large slice of the client runtime.
