# Session, 2026-08-22 into 2026-08-23

Twenty-two commits, almost all of them downstream of one question: *"is the
course defaulted from the round setup, and can I override it?"* Answering that
honestly meant following the venue from the picker to the card it scores
against, and most of what follows was found on the way rather than planned.

## The through-line

The tournament's venue was the last thing in the app chosen by typing a name.
Every other venue — a round's, a match's — is an id. `event/page.tsx` loaded
the club's `Course` rows and **threw the id away** before handing them to the
screen, so the picker had nothing else to pick by.

`Event.courseId` now exists (migration `20260823030000_event_course_id`, hand
written — `prisma migrate dev` wanted a shadow database and failed replaying an
earlier migration into one; CLAUDE.md says fix drift by hand rather than let
anything near the dev database).

The backfill only fills where the club has **exactly one** course of that name.
Two courses sharing a name is the precise ambiguity that made a name a bad key;
guessing between them would point a tournament at the wrong card silently,
which is the failure the column exists to end.

### It was already wrong on real data

Demo Cup read **"Blue Ash Golf Course"** and was scoring against **Pebble
Beach's card**, left behind when the venue changed. Same par by coincidence,
completely different stroke index:

```
by id    1, 7, 5, 11, 15, 3, 13, 17, 9
by name  6, 10, 12, 16, 14, 2, 18, 4, 8
```

A wrong stroke index never looks wrong. It puts the handicap shots on the wrong
holes, in every match, silently. `saveEvent` now clears the event's own card
when the venue changes, which was the cause.

### How the reader migration was made safe

`EventCourseFields` gained an **optional** `courseRef`. Adding the row to a
query is what switches that screen from name to id, so it moved one select at a
time and a caller left alone behaves exactly as before — there is a test
asserting that. If the row's card will not parse, resolution falls through to
the old path: a broken row must not take a working card away.

`COURSE_REF` is the one definition of the join. Written per site it would
drift, and the drift is silent — a select missing `strokeIndex` parses to null
and falls quietly back to name resolution.

**`course-by-id.test.ts` is the guard.** A caller that forgets the join does not
throw and does not look broken; it returns *a* card, computed against a
different stroke index. The sweep found three modules I had not counted —
`handicap-record`, `regroup`, `skins-pot` — which are club handicaps and money.

## One control for picking a course

There were three unrelated interaction models and four copies of the worst:
native `<select>` in `RoundVenue`, `ScoreEntryClient`, `StagesClient` and
`CourseLibrary`, two of them duplicating the "Played at" label and the
`(inherited)` string verbatim.

`CoursePicker` is now that control everywhere: type to narrow, arrows, Enter,
Escape, ranking shared with the directory search. It **narrows** rather than
merely reordering — ranking alone left thirty rows on screen with the good ones
on top, which is the wrong answer to "narrow it down".

It is a list rather than a `<select>` for one reason that pays for the rest: an
`<option>` cannot carry a second line, so it could never show a course's town
or that it has **no card yet**. A club with a Cincinnati and a Columbus
Hillcrest could not tell them apart.

Three rungs, in the order somebody wants them: the club's own courses, then the
wider directory (only when the club's list has nothing), then `Use "<typed>"`.
Non-course choices — "Other", "No fixed course" — sit **outside the filter**,
because somebody typing a name the library lacks is exactly the person who
needs "enter it manually".

## Both venue overrides, and the warning

`setStageCourse` and `setMatchCourse` refused anything not already a venue, and
both pickers hid below two venues. Together, a one-course tournament could not
have a venue corrected from score entry at all. Both now take any course in the
**club's** library and link it on the way, scoped to the organization.

Changing a venue or a format **re-scores** a round that already holds cards.
Not one stroke moves, which is why it needed saying. Both now refuse first,
report the count, and take a deliberate confirm — the shape the field resize
already used.

**"Match play / Stroke play" on Score entry now reads "Match by match / Whole
field"**, and the round's real format is stated beside the venue. Those radios
name an entry method, not a format; on a Match Play round the old label looked
like an offer to change it.

## The catalogue

- The directory is **global**, not American — it only looked US-only because
  `/courses/state/{code}` is the one listing endpoint taking a place. `--world`
  walks it via search + offset.
- **`country_iso` exists only on a search row.** The detail payload has no
  country field, so it is carried from the listing. Reading it off the course
  stored 583 rows blank and nothing said so.
- Rate limits are **per endpoint**, 500/day each, and a *burst* 429 reports
  `Remaining: 0` and a midnight reset — identical to genuine exhaustion. The
  headers cannot tell them apart; only backing off 5s/15s/45s can.
- **Nine-hole courses are now accepted** — 119 of 724 US rows were being thrown
  away. `--recheck` reads the stored refusal reasons and re-fetches only what an
  old rule wrongly refused: 119 requests instead of 471 for a state refresh.
- Search now takes **town and state**: "Ohio", "OH", "Cincinnati, OH".
  Non-US rows have no state and usually no city, and **no non-US course has a
  usable card** — the directory has none for 86% of them.

## Things that bit, worth not repeating

- **A guard that refuses a real golf course is worse than no guard.** Extending
  the card checks made par-3 courses unstorable (9 holes = 27, below a range
  that assumes a regulation course). Sorted-par detection is now 18-hole only:
  nine values across three pars is too small a sample.
- **A refusal nobody sees is not a refusal.** `CourseSetupPrompt` called
  `void saveCustomCourse(...)`, discarding the result — harmless until the
  action could refuse, then the screen closed on a save that never happened.
- **Two shapes of score, two readers.** The re-score guard counted stroke blobs;
  match play stores none — a hole result lives on the `Match`. A round with 48
  results reported zero and the change sailed through.
- **The gate you edited may not be the one doing the work.** `RoundVenue` had an
  early `return null` above the condition I changed.
- Running it beats reading it. The "Ohio returns 5 not 471" bug, the NUL byte in
  a test about smuggling bytes, and `--recheck` reporting "0 courses" because a
  `\d` collapsed to `d` were all found by execution.
