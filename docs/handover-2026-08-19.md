## The decision that blocks the rest of the onboarding

**Is onboarding event-first or club-first?** Ajay's call.

Every screen in the `(app)` shell goes through `requireScreen` ->
`requireEventSession`, which redirects to `/choose` without an active event.
`/organization` additionally resolves its organization THROUGH the event
(`event.organizationId`). So an organizer who has just signed up **cannot reach
Club settings or the roster at all**.

The queued flow — "land on Club settings, then walk members -> tournament" — is
inverted relative to how the app is built. Two ways out:

1. **Make the org screens event-free.** `/organization` resolves its org from
   the user's owner/admin membership when there is no active event, behind a
   guard that is not `requireEventSession`. This is what the original request
   described. It touches an authorization path, so it wants care.
2. **Keep onboarding event-first.** A new organizer lands on `/choose`, which
   already says "Welcome to TourneyHQ / Your account is ready" and already
   carries `CreateFirstTournament`. Mount the checklist there. Club settings
   become reachable one step in, once the first tournament exists.

(2) is much cheaper and fights the architecture less. Building the wrong one
means building it twice.

## Settled on 2026-08-18, do not reopen

- **Org kinds are `club | community | personal`**, and
  `lib/domain/org-profile.ts` is authoritative — the schema comment now says
  so. `course` was dropped: it answered all five behaviour flags exactly as
  `club` did, so it was a label rather than a kind. The word survives in the
  sign-up wording ("A golf club or course"), which is where somebody recognises
  their own outfit.
- **`tracksCash` is gone.** It was read by nothing and held the same value as
  `ledger` on every kind. Do not reintroduce a second flag for "does the app
  count money" — a stake in a pot is a RESULT and is true for everybody; a
  share of the minibus is a DEBT and that is `ledger`.
- **`moneyLayoutFor` is gone**, for the same reason: it decided the ledger
  question from the org kind, which `resolveMoneyMode` already owns.
- **A club sees the money screen when it has pots.** `sharedCostsApply(mode)`
  is the ledger/kitty; `moneyScreenApplies({mode, hasPots})` is whether the
  screen exists. Do not collapse them back into one flag.

## Traps, learned the hard way

- **Read a file before writing it.** `SetupChecklist` (per tournament) already
  existed and was overwritten with `Write`; only the typecheck caught it. The
  org-level one is `OrgSetupChecklist` for that reason.
- **Do not invent a route.** All five checklist hrefs were made up and every
  row was a dead link for weeks. `SETUP_HREF` is now swept against the
  filesystem by a test. Check paths with
  `find src/app -name page.tsx`.
- **A test that agrees with the code is not evidence.** The render test
  asserted the same invented `/tournaments/new` the code used.
- **A summary is not evidence.** An earlier summary claimed D1–D9 were closed;
  re-reading the source found D5 and D6 still open.
- **Windows/CRLF:** `perl -0pi -e` multiline patterns fail, and node scripts
  with template literals mangle escapes (`\d` became `d`, silently breaking a
  parser). **Use the Edit tool for structural edits.**
- **Scripts cannot import the services** without the shim — they open with
  `import "server-only"`, which throws outside Next:

      npx tsx --require ./scripts/server-shim.cjs scripts/your-script.ts

  A script using only `PrismaClient` (like the backfill) needs no shim.
- **Hiding a section is not the same as not creating something.** The first
  attempt at "don't default the round" hid the whole block, swapping a silent
  creation for a silent omission.
- **`git add -p` is unavailable here** (no interactive flags). To split a
  commit when one file spans two, reconstruct the intermediate file state, and
  verify a commit in isolation with a throwaway
  `git worktree add --detach` at that SHA — node_modules resolves from the repo
  root above it.
