## What is in place

- **`RoundHandicap`** — a row per round per player, `override` / `frozen` /
  `frozenAt`, `@@unique([stageId, playerId])`. Migration `46_round_handicap`:
  one CREATE TABLE, two indexes, one FK, read before applying. **No row means
  the roster handicap**, so an event with no rows behaves exactly as before.
- **The freeze** — `freezeRoundHandicaps` in `src/lib/services/round-handicap.ts`,
  called by all four doors that store a returned card (stroke, net match, team,
  import). Writes `handicapToFreeze` for every confirmed player, only where
  `frozen` is null; `frozen: null` on the update and `skipDuplicates` on the
  insert make the database, not the read, decide a race.
- **`isReturnedCard`** — a card ROW is not a returned card. A cut writes an
  empty card for every survivor, and freezing on the row would tell an organizer
  cards were in a fortnight before anyone teed off.
- **Clearing a whole round releases the freeze**; clearing one card does not.
- **Every scoring path** resolves through `roundHandicapOf`: the board (via
  `strokeHandicapResolver`), net match play, the net importer, and both team
  paths.
- **The screen** — `RoundHandicaps` on each playing round in `StagesClient`.

## Decisions made this session, on top of the six already settled

1. **Flights, seeding and the draw stay on the ROSTER handicap.** An override
   says what somebody receives in one round; it is not a claim about how good
   they are. A visitor given two shots for an afternoon must not change flight
   for the week. Written into `hcpOf` in `loadEventState` so it is a decision
   rather than an omission.
2. **A clone carries no round handicaps.** `clone.test.ts` forces the choice.
   Last year's rounds were played off last year's handicaps, on entries a copy
   does not carry.
3. **The override is NOT behind `isSetupLocked`.** A wrong handicap is noticed
   when the tournament is live, which is exactly when it must still be fixable.
   The freeze is the lock, per decision 5. The round's ALLOWANCE stays governed
   by `isSetupLocked` as a round setting.
4. **"Apply to the rest" writes later rounds only**, each as its own fact, and
   skips frozen rounds rather than refusing — it reports how many it left.

## One behaviour change, deliberate — read this

`recomputeTeamMatch` scored a side off `Player.handicap`, the roster **Index**,
unconverted, while the Teams screen showed the same side converted for its tees
through `teamsForStage`. A club that rates its tees was **shown one side
handicap and scored by another** — the 2026-08-12 audit's defect in the one
place nobody had looked. Both read the same conversion now.

**This changes team match scoring for any club with rated tees**, in the
direction the rest of the app already scored. Clubs with no ratings are
unaffected, because a Course Handicap off an unrated tee is the index.

## Also fixed in passing

`prisma format` was **injecting a line** into `schema.prisma` on every run: the
`logoUrl` doc comment had grown nine `* /**` lines, and each format run added
another. The trigger is a `//` line comment immediately followed by a `/** */`
block on a field. A blank line between them stops it. The junk is gone and the
file is stable across repeated `prisma format` runs — worth knowing before
someone "cleans up" that blank line.

## Rounds played before the freeze existed — and the decision not to backfill

Found by checking the control against the Demo Cup, which holds seven scored
cards in round two and no frozen rows: **every round played before this shipped
has cards and nothing frozen**. The screen offered to change those players'
handicaps and the action would have taken it, re-pricing cards already in. The
cause was asking "is a frozen row there" where `acceptsHandicapChange` was
always meant to be asked "has this round been SCORED".

Fixed in `a2541af`: `roundHasReturnedCard` asks the real question across all
three card shapes, and the screen, the override action and "apply to the rest"
all read it. Both write paths also FREEZE such a round on the way past, at the
value the board is already using — refusing alone is not enough, because a
played round with nothing frozen is still resolved live.

**Ajay decided on 2026-08-22 not to run the backfill.**
`scripts/freeze-played-rounds.ts` exists, is idempotent and dry-runs by default;
it was applied to the DEV database (33 player-rounds in Demo Cup round two,
verified to change no number and then proved to hold when a roster handicap was
moved 2.1 → 10.1). **Production has NOT been backfilled.**

What that leaves exposed, stated plainly: a production round that is **finished**
— so it will never receive another card — and whose players' handicaps are
**later edited on the roster** will still re-score. Any round that receives one
more card freezes itself, and no round can have its handicaps edited from the
screen any more. Run the script if that combination ever matters:

    npx vercel env pull .env.production.local
    set -a; . .env.production.local; set +a
    npx tsx --require ./scripts/server-shim.cjs scripts/freeze-played-rounds.ts

## Notes for whoever is next

- **The audit suite is not in the gate CLAUDE.md prescribes.** The behavioural
  proof of this feature lives in `round-handicap.audit.test.ts` and
  `round-handicap-scoring.audit.test.ts`; the default run only sees the
  source-text checks in `handicap-wiring.test.ts`. CLAUDE.md now says to run
  `npx vitest run --config vitest.audit.config.ts` for anything provable only
  against real rows.
- **`handicap-wiring.test.ts` asserts on source text on purpose** — the bug it
  guards has no runtime symptom on an unrated course. Two assertions were
  re-pointed at the guarantee (both resolutions, in order) rather than loosened,
  and a new one covers the team path. Behaviour is now also asserted against a
  rated tee in the audit suite, where an ignored override loses every hole.

  `scripts/verify-round-handicaps.mjs` mints a session for a throwaway organizer,
  drives `/stages` through all four states and removes its own fixtures. That is
  what found the legacy-round bug above. Run it with SMOKE_BASE_URL set to
  whichever port a dev server is on.
